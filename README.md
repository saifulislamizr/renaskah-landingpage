# Renaskah, Website

Bilingual (Bahasa Melayu + English) conversion-focused landing page for
Renaskah's Proofreading & Formatting services. Next.js 16 (App Router)
+ TypeScript + Tailwind CSS v4. No backend, the quote form builds a
WhatsApp message client-side and hands off to `wa.me`.

Narrative: Problem, Frustration, Solution, Transformation, Proof,
Trust, Pricing, Easy Process, CTA. Public full pricing is intentional
here (an explicit, later instruction overrode the vault's original
"don't show pricing" rule, see `src/content/pricing-data.ts`).

## Getting started

```bash
npm install
npm run dev      # http://localhost:3000 (redirects to /ms)
npm run build    # production build
npm run start    # serve the production build
npm run lint
```

## How the site is organized

```
src/
  app/
    [locale]/          # locale is "ms" or "en", this IS the root layout
      layout.tsx        # <html>/<body>, fonts, per-locale <head> metadata
      page.tsx           # assembles every section in narrative order
    sitemap.ts / robots.ts
    icon.png, apple-icon.png, favicon.ico, opengraph-image.png
  proxy.ts               # redirects "/" -> "/ms" (Next 16's proxy = old middleware)
  content/
    schema.ts             # the TypeScript shape ALL page copy must match
    ms.ts / en.ts           # the two full, independently-written translations
    pricing-data.ts         # public pricing, one source of truth for both locales
    testimonials-data.ts    # shared (non-translated) testimonial image list
    before-after-data.ts    # shared before/after sample asset paths
  components/
    layout/      Navbar, Footer, FloatingWhatsApp, LanguageSwitcher
    sections/    one component per landing-page section, in page.tsx order
    quote-form/  QuoteForm.tsx, the Proofreading/Formatting quote form
    pdf-viewer/  PdfCompareSlider (drag compare) + PdfCompareViewer (full doc)
    ui/          Button, Field, SectionHeading, Highlight, HighlightedText,
                 CountUp, ScrollReveal, useInView, icons.tsx (hand-rolled)
  lib/
    locale.ts    locale list/type/helpers
    whatsapp.ts  WhatsApp number + message builders (the ONLY place that builds
                 the quotation message)
public/
  images/logo/            generated from the vault's master logo PNG
  images/testimonials/    real, redacted WhatsApp screenshots (see below)
  images/before-after/    real before/after formatting sample (PDFs)
  pdf.worker.min.mjs      pdf.js worker build, regenerated by `postinstall`,
                          don't hand-edit (see PDF viewer section below)
```

**Content is fully separated from presentation.** No section component
hardcodes copy, everything comes from `content/ms.ts` / `content/en.ts`
typed against `content/schema.ts`. To change any text on the site, edit
those two files, no component changes needed.

**Punctuation rule:** no em dash anywhere in copy that renders on the
page (headings, paragraphs, buttons, testimonials, FAQ, alt text, aria
labels). Use commas, periods, colons, or shorter sentences instead.
This applies to `content/ms.ts`, `content/en.ts`, and any literal
string inside a component that a user actually sees, code comments are
fine.

## Keyword highlights

`HighlightedLine` (`{ lead, keyword, tail }`) in `content/schema.ts` is
how a headline picks one phrase to visually emphasise instead of the
whole sentence. `lead`/`tail` carry their own spacing/punctuation (no
auto-inserted spaces), e.g. `{ lead: "Dah betulkan ", keyword: "page
number", tail: ", bahagian lain pula berubah." }`. Render it with
`<HighlightedText line={...} />` inside whatever heading tag the
section needs. The `Highlight` component underneath draws the
marker-style background in on scroll (`.mark` / `.mark-copper` /
`.mark-teal` in `globals.css`), once, respecting
`prefers-reduced-motion`.

`CountUp` (used for the "300+" stat in TrustBar) and `ScrollReveal`
(stagger-capable fade/rise, used for the problem-section pain points,
pricing cards, testimonial cards) share the same `useInView` hook, so
every scroll-triggered animation on the page fires once and never
restarts on subsequent scrolling.

## Colour accents

Two accents only, deliberately capped: **copper** (brand primary, also
the Proofreading accent) and **Ink Teal** (`--color-teal-*` in
`globals.css`, the Formatting accent, a second "colour of ink" next to
copper). Don't introduce a third.

## Adding/replacing testimonials

Edit `src/content/testimonials-data.ts` and drop the matching image in
`public/images/testimonials/`. The carousel renders whatever is in
that array, in both locales, automatically.

**All 17 testimonials are used**, pre-blurred by the business itself
(contact name and avatar covered in every header/quoted-reply
occurrence) and supplied as a finished set. No name is displayed
anywhere in the UI, `TestimonialItem` has no `name` field and
`Testimonials.tsx` renders no figcaption, only a generic, localized
`imageAlt` on each image. If a future batch isn't pre-blurred, redact
it before adding it here rather than relying on the component to hide
anything.

If you replace an image at the same filename, clear `.next/cache`
before rebuilding, Next's image optimizer caches by path and can serve
a stale render of the old file otherwise.

## Before/After

Two layers, both reading from the same real sample PDFs
(`public/images/before-after/*.pdf`), nothing fabricated:

- **`PdfCompareSlider`**, the headline proof moment. A draggable
  before/after comparison rendered live via pdf.js canvases (not
  static exported images), with page-jump chips
  (`content.beforeAfter.pages`, currently Table of Contents / List of
  Tables / Chapter 1 heading / cover page, verified against the actual
  PDF text content, not guessed).
- **`PdfCompareViewer`**, kept underneath behind a "Lihat Dokumen
  Penuh" disclosure. Desktop shows both documents side by side with
  synchronized page, zoom, and mirrored scroll; below `lg` it's a
  single pane with a Before/After tab toggle. Download links for both
  PDFs stay at the bottom as a separate, clearly optional action.

To add another before/after pair, add another object to
`beforeAfter.examples` in each locale file (with its own
`beforeHref`/`afterHref`) and drop the two PDFs in
`public/images/before-after/`, `BeforeAfter.tsx` renders one slider +
viewer per example. If the new pair has different meaningful pages,
update `beforeAfter.pages` too.

### pdf.js worker

`public/pdf.worker.min.mjs` is copied from the installed `pdfjs-dist`
version by `scripts/copy-pdf-worker.mjs` on every `npm install` (the
`postinstall` script), rather than resolved via a CDN or bundler asset
URL, both are common sources of pdf.js version-mismatch errors. If you
bump `pdfjs-dist`, just reinstall.

## Pricing

`src/content/pricing-data.ts` holds the 12-tier rate table (30 days
down to 3 hours) for both services, sourced verbatim from the vault's
internal pricing document. Each locale file only supplies its own
turnaround-label wording (`formatTurnaroundMs` / `formatTurnaroundEn`),
the rates themselves are pre-formatted strings shared by both, so
there's exactly one place to correct a number if it ever changes.
`components/sections/PricingTable.tsx` renders one card (reused for
both services), `Pricing.tsx` lays out the pair.

## WhatsApp / quote logic

`src/lib/whatsapp.ts` is the single source of truth for the WhatsApp
number and the two message templates (Proofreading / Formatting). The
quote form itself (`components/quote-form/QuoteForm.tsx`) never
computes a price, it only builds the structured WhatsApp message,
quotation happens over WhatsApp after a human reviews the enquiry.

## Deploying to renaskah.com

Any Next.js host works (Vercel, or a Node server / Docker per the
[self-hosting guide](https://nextjs.org/docs/app/getting-started/deploying)).
Point the domain's DNS at the host, then update `SITE_URL` in
`src/app/[locale]/layout.tsx`, `src/app/sitemap.ts` and
`src/app/robots.ts` if it ever changes from `https://renaskah.com`.

## Known non-issues

- `next build` prints a `metadataBase ... using "http://localhost:3000"`
  warning. It only affects the build-time log for the top-level
  file-convention routes (icon/OG-image/sitemap, which sit outside the
  `[locale]` tree); `metadataBase` **is** set correctly for real page
  requests via `generateMetadata` in `app/[locale]/layout.tsx`, and the
  actual deployed OG tags resolve against the real request host.
